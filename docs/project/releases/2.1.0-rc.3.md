# Semantic Code Intelligence 2.1.0-rc.3

Status: candidate identity assigned; bytes are not frozen until a dedicated AK validation task completes.

Support authority: [ADR-0004](../../adr/0004-local-single-user-production-candidate.md)

Preparation contract: [local-single-user-release-preparation.md](../local-single-user-release-preparation.md)

## Identity and baseline

`2.1.0-rc.3` is the install-doc hygiene candidate succeeding published 2.1.0-rc.2. The repository has no
previous Git tag or GitHub release baseline, and there is no authoritative released `2.0.0` range.
These notes therefore curate owner-verified work since the initial local production-candidate
implementation at commit `1aca36c8`; they do not pretend that `2.0.0` was distributed or formally
released.

This cut exists so bundled install examples can use `${SCI_VERSION}` without rebinding
the published `2.1.0-rc.2` archive. Exact bytes are not frozen until a dedicated validation
task completes. After that bind, `2.1.0-rc.3` must never name different runtime bytes.

## What changed in 2.1.0-rc.3

- Bundled README install examples use `${SCI_VERSION}` instead of a hard-coded archive name.
- Runtime payload entries remain globally lexicographic by package-relative path before digesting
  and evidence serialization, replacing the per-directory traversal order of earlier candidates.
- Packaged runtime wrappers are normalized to mode `0755` before packing and verified after
  extraction; wrapper mode is part of each manifest entry and of the repeatable payload digest.

## Intended user and supported runtime

This candidate is for one trusted local operator using one trusted repository at a time.
Production-candidate support is limited to:

- a reviewed local `semantic-code-intelligence-2.1.0-rc.3.tgz`;
- the installed `semantic-code-intelligence` and `sci` CLI bins;
- the installed `semantic-code-mcp` stdio bin;
- preview-first mutation, with guarded apply remaining explicit;
- contained runtime state under the target repository's `.ontology` directory.

The bundled `README.md` owns install, checksum, PATH/bin discovery, CLI, MCP-stdio, upgrade, rollback,
and uninstall instructions. The bundled `CONFIG.md` owns workspace, state, and environment settings.

## Highlights

### Composite-first agent workflows

SCI exposes first-class composite workflows for the high-value paths that previously required agents
to assemble raw search/navigation primitives themselves:

- `explore_symbol_impact` for bounded change-impact orientation;
- `locate_confirm_definition` for confirmation before edit planning;
- `rename_safely` for preview-first rename planning and checks;
- `structural_patch_checks`, `patch_checks_in_snapshot`, and `safe_write` for staged patch/check flows.

These are workflow contracts, not whole-program semantic guarantees. Native Pi use additionally needs
a compatible private `pi-semantic-code-intelligence` bridge prepared separately under AK task `4901`.

### Progressive, decision-first impact evidence

`explore_symbol_impact` now uses three explicit disclosure modes:

- `compact` is the bounded default decision packet;
- `standard` adds sparse normalized evidence under `details.schemaVersion: 2`;
- `debug` adds separately bounded and redacted subcall diagnostics, timings, shape failures, and raw
  fragments.

Unconfirmed packets do not authorize edits. They distinguish backend-observed graph claims from
normalized usable evidence, explain omissions, and return a complete bounded
`locate_confirm_definition` recovery action with exact safe arguments.

### Structural edit-risk signals

Impact packets derive public-API, state, registry, and test risk only from target-specific structural
evidence where available. Conventional path/name matches remain low-confidence naming fallback and
do not become detections. Structural evidence proves bounded syntax, not framework identity,
persistence, aliasing, or whole-program semantics.

### Safe definition boundaries and truthful MCP telemetry

- No definition remains a structured non-error empty result.
- An outside-workspace definition context remains an error with stable reason `outside_workspace` and
  bounded remediation, without the submitted path, host path, stack trace, or raw diagnostics.
- MCP telemetry treats a resolved tool result carrying `isError: true` as an application failure even
  when JSON-RPC transport itself completed successfully.

### Installed candidate lifecycle

The local artifact gate packs the runtime twice, rejects duplicate/source-only members, compares
sorted per-file payload manifests, installs the archive in isolation, and exercises installed CLI and
MCP stdio against a non-mutating fixture. Installed lifecycle documentation now distinguishes every
source-checkout command from commands actually present in the tarball.

## Compatibility notes

- Package, CLI, MCP server metadata, and archive identity are all `2.1.0-rc.3`.
- Standard `explore_symbol_impact` details use normalized schema version `2`; consumers that inspect
  standard details must accept that schema rather than relying on the earlier shared raw detail shape.
- Compact remains the default and preserves fail-closed unconfirmed behavior.
- Observed graph claims and normalized usable graph evidence are separate counts and states.
- No-definition is non-error; outside-workspace input is an error with only allowlisted recovery data.
- CLI and MCP stdio are the only production-candidate interfaces. Alpha HTTP/MCP HTTP/LSP contracts
  are not promoted by this candidate.
- The installed CLI includes the explicit experimental command
  `semantic-code-intelligence experimental structural-evidence-receipt`. It remains outside the
  CLI/MCP-stdio production-candidate commitment and is not registered as an Alpha MCP/HTTP tool.
- Repository closeout receipt tooling remains source-checkout-only validation tooling; it is not in
  the installed runtime and does not carry release authority.

## Internal reliability, not product features

The candidate lineage also removes two sources of CI-like batch contamination:

- non-persistence Layer 4 tests no longer share repository-global SQLite state;
- millisecond circuit-breaker tests use deterministic system-time advancement rather than wall-clock
  races.

These changes support candidate confidence. They are not user-facing features, adoption evidence, or
performance/SLO proof. Governance task-scope snapshots are likewise internal authority/evidence
plumbing rather than runtime functionality.

## Known limitations

- The tarball does not vendor its runtime dependency closure. Bun may resolve dependencies from an
  operator-approved registry or local cache, and the current `--no-save` installation retains no
  dependency lock. The candidate is not an offline or hermetic bundle.
- Trusted repository checks can execute constrained commands; SCI is not a hostile-code sandbox.
- Runtime state and snapshot artifacts are local. SCI is not a canonical task, decision, direction,
  release, or durable evidence authority; use Agent Kernel for those facts.
- HTTP, MCP HTTP, LSP, Docker, Compose, Kubernetes, hosted operation, non-loopback production use,
  untrusted repositories, multiple users, multiple tenants, public package publication, production
  availability, and p95/p99 SLOs are unsupported.
- IW77 closed with six eligible episodes, zero terminal-valid episodes, and zero admissible packaged
  interface successes. This candidate therefore makes no broad adoption, call-economy, general
  effectiveness, or product-market-readiness claim.
- The rejected standard-mode efficiency threshold from the bounded disclosure campaign is not
  converted into a performance claim.

## Upgrade, rollback, and removal

Install every reviewed candidate in a fresh version directory and switch only the physically checked
`current` symlink after absolute-path CLI/MCP-stdio smoke. Keep the prior version for rollback. Never
overwrite a version directory or reuse `2.1.0-rc.3` for changed bytes.

Upgrade, rollback, and uninstall do not authorize deletion or migration of a target repository's
`.ontology` state. Data retirement requires a separate owner-approved backup and deletion action.

`2.1.0-rc.1` and `2.1.0-rc.2` remain the published releases. These notes still do not authorize a tag, GitHub release, npm publication, or deployment for `2.1.0-rc.3`.

Green Alpha MVP CI on later `main` commits is source-checkout evidence, not a rebind of any
