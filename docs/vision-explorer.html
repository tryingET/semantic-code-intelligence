Semantic Code Intelligence

A repository's living code memory: fast search, AST structure, symbol planning, semantic graph context, and learned patterns for humans and harnessed LLM coding sessions.

Not “agents” in the vague sense.

Agent is overloaded. This vision means harnessed LLM coding sessions: LLMs operating inside Pi, Claude Code, Cursor, or another tool/runtime workbench.

Humans are developers. Software parts are adapters, services, or processes.

05
Implementation Phases

      

        
Phase A — Stabilize
One unified code brain, normalized contracts, snapshot ids, clean stdio, visible latency metrics.

        
Phase B — Safe Edits
Overlay + patch proposals, reviewable diffs, format/lint/typecheck/test evidence before acceptance.

        
Phase C — Precision
SCIP/LSIF indices and feature-flagged LSP boosters for typed rename and implementation lookup.

        
Phase D — Semantic Memory
StoragePort adapters for SQLite, Postgres, and triple stores; budgeted ontology enrichment; pattern learning as suggestion, not hidden policy.

        
Boundary
The core is not task authority, governance authority, or an unbounded autonomous editing system.
